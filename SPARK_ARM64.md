# ARM64 / NumPy 2 compatibility on current upstream main

This branch starts at upstream main `5225ea50e6e8c604c967a914f441db7d756e5a0a`,
which already includes the merged ARM64 build support PR #126. It is not a
backport to v0.1.1. Package versions are generated by the upstream SCM backend.

Additional changes are limited to stable pybind11 2.13.6 for NumPy 2 bindings,
filtering missing optional include directories exported by Ubuntu OMPL, and
allowing the FCL header's dangling-else warning under GCC 13. Other warning
errors and upstream release optimization flags remain enabled.

Validated build platform: Ubuntu 24.04, Linux aarch64, CPython 3.12, NumPy 2.5.4
and GCC 13. Native dependencies: Eigen 3.4, OMPL 1.5.2, haosulab/fcl at
`89378e70290d4756cc6f74d6a0bf8e6e0d0f57aa`, Pinocchio 2.6.21,
CppAD 20240000.1, Assimp 5.3, Orocos KDL 1.5.1 and urdfdom 4.0.

Build native dependencies into a private prefix, with Pinocchio Python/tests
off and URDF/autodiff on. Expose that prefix through CMAKE_PREFIX_PATH and its
headers through CXXFLAGS. The Python build environment needs build, setuptools
<81, setuptools-git-versioning <2, libclang 18.1.1 and NumPy. Set
CMAKE_BUILD_PARALLEL_LEVEL=4 and run `python -m build --wheel --no-isolation`
from the repository root. `auditwheel repair --plat manylinux_2_39_aarch64
--strip` bundles native dependencies for an Ubuntu 24.04-specific wheel.
Upstream and bundled dependency licenses continue to apply to distributions.

Regression check against the installed package:

```sh
python /absolute/path/to/this/repo/tests/test_numpy2_binding_smoke.py
```

The main-branch planning API uses `mplib.Pose` and `Planner.plan_qpos` /
`Planner.plan_pose`. Consumers pinned to v0.1.1 must update their calls and
explicitly resolve their dependency requirements; this branch does not label
new APIs as v0.1.1 or replace them with the old implementation.
